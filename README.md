# 台股新聞資料｜Pipeline 交接說明

本階段負責收集新聞、整理日期、去除完全重複的正文，並標記台股關聯。下一階段負責事件整合、市場解讀與預測。

## 1. 下一階段讀哪個檔案？

讀取 `data/tw_news_YYYY-MM-DD.json`。內容是 JSON 陣列，每個物件代表一篇新聞；沒有資料時為 `[]`。

| 檔案 | 用途 |
|---|---|
| `tw_news_日期.json` | Pipeline／agent 的主要輸入 |
| `tw_news_日期.csv` | 同一批資料，供人工檢查 |
| `report_日期.json` | 確認原始篇數、保留篇數、排除原因與來源錯誤 |

`.cache` 是原始資料快取，下一階段通常不需要讀取。自動分析請使用 JSON，保留原始文字。

## 2. 重要欄位

| 欄位 | 意義 |
|---|---|
| `id` | 由文章網址產生的識別碼，同網址更新仍是同一 ID |
| `title`、`content` | 新聞標題、正文 |
| `source`、`url` | 新聞來源、原文連結，供引用與查證 |
| `published_at` | 發布時間，已轉為台灣時間（UTC+8） |
| `fetched_at` | 這份內容的抓取時間，帶有時區 |
| `relevance_tier` | 台股關聯分類，見下表 |
| `content_status` | 正文品質標記，見下方說明 |
| `filter_reason` | 分類與保留原因 |
| `category`、`language` | 原站分類、語言；英文新聞沒有翻譯 |

| `relevance_tier` | 下一階段怎麼用 |
|---|---|
| `core` | 台股核心候選，優先分析 |
| `context` | 海外總經／產業背景，先確認與台股的連結 |
| `review` | 關聯尚未確認，仍保留，由 agent 或人工判斷 |

以上分類由關鍵字規則產生，**不是影響方向、重要性分數或已驗證的因果關係**。

`content_status` 為 `extracted_unverified`：已取得正文，但未人工確認完整性；為 `short_or_missing`：本輸出中代表達到最低長度的短文，仍需注意是否不完整。

## 3. 使用前必須知道

- **日期是發布日，不是最近 24 小時。** 凌晨執行只會收錄當天午夜以後的新聞；前一天晚間消息需另外納入分析時間窗。
- **目前已做的處理：**同網址合併、完全相同正文去重；排除明確美股行情速報、受限正文和少於 40 字元的正文。相同事件的不同報導仍可能同時存在。
- **預測要控制時間：**確認發布與抓取時間都不晚於預測截止時間。同日重跑會更新同名檔案，現有資料不能重建所有歷史版本。
- **篇數不代表市場沒有消息。** 近期列表可能漏文、來源可能無法存取，且目前不支援完整歷史回補。資料少或為空時，先查報告，不要直接當成「無市場事件」。
- **來源不是七站都有資料。** 部分來源因存取或用途限制停用／失敗，以報告中的實際結果為準。

交給 agent 時，請要求每項結論附文章 ID 與網址，區分新聞事實和推論；新聞內文應視為資料，不應當成指令執行。

## 4. 需要自己產生資料時

Windows、Python 3.10 以上。首次執行 `install.bat`，之後執行 `run_today.bat`，結果存入 `data`。不需要 LLM API key。

指定日期可在程式資料夾開啟 PowerShell 執行：

```powershell
.\.venv\Scripts\python.exe -X utf8 crawler.py --date 2026-10-16
```

這個日期參數只篩選目前列表找得到的新聞，不保證能補齊該日所有文章。
